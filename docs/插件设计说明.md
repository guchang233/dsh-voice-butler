# 语音管家 · 设计说明

> 一句话：**语音壳只管嘴和耳朵，脑子搬进了 DSH。**
> 这一篇说清谁负责什么、为什么要这么切、以及踩过的坑。

---

## 1. 为什么要重切

上一版把「语音」和「对话」缝在一起：壳自己调 DeepSeek、自己维护 26 个工具、自己做确认闸门、自己写聊天记录。
结果有三处重复：

- 工具层重复（DSH 有 shell / fs / web，壳里又写了一遍 UIA 那套）
- 上下文重复（壳的 jsonl 和 DSH 的会话是两本账，谁也不是真的）
- 确认逻辑重复（壳问一遍、DSH 再拦一道）

新版把边界画在**「听/说」和「想/做」之间**：

```
┌─────────────── 语音壳（Electron） ───────────────┐
│ 麦克风 → 唤醒词 → 端点检测 → ASR ─┐              │
│                                   │ 一句话       │
│ 喇叭 ← TTS ← 分句 ← 帧 ◄──────────┼── 面板显示   │
└───────────────────────────────────┼──────────────┘
                                    ▼
                         POST /voice/say
                                    │
┌────────────────────── DSH ────────┼──────────────┐
│ butler-bridge ──► 会话「DSH语音管家」（管家模式） │
│      ▲                    │                      │
│      └── 会话事件 / 逐字增量 / 工具 / 确认        │
└──────────────────────────────────────────────────┘
```

壳里**没有任何**对话状态：杀掉重开，上下文一条不少，因为上下文在 DSH 的会话日志里。

## 2. 三块拼图

### 2.1 语音壳（`app/`）

| 文件 | 职责 |
|---|---|
| `main/voice.ts` | 语音状态机：`idle → listening → thinking → speaking`；唤醒、断句、识别、念稿、插话打断 |
| `main/bridge.ts` | 与 DSH 的 HTTP 通道：投递一句话 + 长轮询取帧；断线重连、地址发现 |
| `main/audio/kws.ts` | 本地离线唤醒词（sherpa-onnx zipformer） |
| `main/audio/vad.ts` | 能量端点检测、WAV 封装 |
| `main/speech/asr.ts` `tts.ts` | DeepSeek 语音识别 / 合成（流式 PCM） |
| `main/windows.ts` | 悬浮球 / 面板 / 顶部特效层（三层窗口） |
| `renderer/panel/App.tsx` | 只做显示：把帧铺成对话流 |

关键取舍：**念稿用「逐字增量」，成稿用 `reply` 兜底**。
壳把 `delta` 喂进按句切分的队列（`SentenceChunker` → `TtsQueue`），`reply` 到达时先把队列里剩下的一句冲出去；
如果这一段模型没走流式（常见于工具调用之后），`reply` 会一次性念完。

状态机的三个细节（都是实测踩出来的）：

1. 唤醒词引擎建流后必须先灌 500 ms 静音且**不能 reset**，否则第一个音节被吃掉。
2. 命中后 reset，要再补一段静音垫底，否则紧接着再喊一次会漏。
3. 播报中允许「唤醒词打断」；能量插话默认关（扬声器回声会骗到自己）。

### 2.2 桥（`butler-bridge/`）

DSH 插件，一条前缀路由 `/voice`：

- `say`：`sessionController.prompt()` 投进会话（`mode: 'queue'`）
- `frames`：长轮询。数据来自三个 Host 事件
  - `session/event` → `user/message`、`assistant/message`、`tool/call`、`tool/result`、`turn/start`、`turn/end`
  - `agent/assistant-stream` → `text-delta` 逐字增量
  - `agent/status` → 运行/空闲
- `approve`：`approval/request` waterfall 上代签，**只接管家会话**，且只在壳正在取帧时接
- `stop` / `new`：打断、换会话

会话自己管：`state.json` 记 id，找不到就按 `cwd`+预设 `butler` 新建并改名「DSH语音管家」。
`endpoint.json` 每 20 秒把 DSH 地址写给壳。

### 2.3 模式（`dsh-preset/`）

预设 `butler`，在模式选择器里叫**管家模式**，和标准 / 极简 / 创造并列。

- persona：管家人格。短句、口语、不要 Markdown（因为要被念出来）、先看后动、不复述过程
- 工具：持久 PowerShell（Windows）/ bash（其它平台）+ fs + 搜索 + web + skill
- 压缩：自带 `compaction-basic`（`auto: true`），长会话不至于撑爆

**踩到的坑**：整机的全局提示词（`Xsdsh-purge` 用 `systemPrompt.section` 在根上下文注册）会把「你叫 Xs」这类设定叠到任何会话上，预设撤不掉它。
解法是两条腿：

1. 人格 prefix 写清「语音通道」的处境与规矩；
2. 再用 persona 的 `suffix`（渲染顺序 10200，排在全局注入之后）做一次末位覆盖：
   被问「你是谁」只答「我是管家」，不要提 Xs / DeepSeek Harness / 模型身份。

实测：加 suffix 之前，唤醒后第一句是「我是 Xs…喵」；加了之后是「我是管家。主人稍等，我看下时间。」——并且真的去调了 `pwsh Get-Date`。

## 3. 帧协议

见 [butler-bridge/README.md](../butler-bridge/README.md)。一句话概括：

```
hello | state | user | delta | reply | tool(start/end) | approval(-done) | error | reset
```

所有帧带单调递增的 `seq`；面板只追加，不重排。相邻 `delta` 在桥里合并，避免一次取回碎成一万条。

## 4. 确认怎么走

1. 工具要确认 → Host 抛 `approval/request`（waterfall）
2. 桥判断：是管家会话？壳最近 25 秒在取帧？（否则 `next()` 交回 DSH 界面）
3. 接走后推 `approval` 帧 → 面板弹卡片、壳用嘴问一句「要…，可以吗？」
4. 壳同时听 9 秒：说「可以」→ `allowed-once`；说「不要」/ 点取消 → `rejected`
5. 90 秒没人理 → `cancelled`，工具调用不会挂死

> 本机当前 profile 的 approval 策略是 `never`（自动放行），所以这条路径平时不会触发。
> 换成 `ask` 之后卡片就会真的弹出来。

## 5. 连续对话

开关在设置里，运行时的节拍全在 `voice.ts`：

```
reply 到齐 → 念完（按字数估个说话时长）→ 自动 beginListening()
   ↑                                            │
   └── DSH 下一轮 ◄── ASR + /voice/say ◄────────┘
```

三道刹车，避免「一直占着麦克风」：

| 情况 | 处理 |
|---|---|
| 说「没事了 / 先这样 / 没有了 / 拜拜」等收尾话术（且整句 ≤16 字） | **不进 DSH**，本地回「好，有事再叫我。」，退回待唤醒 |
| 自动收音后 15 秒没人说话 | 静默退回待唤醒 |
| DSH 还在跑（`state.running`）、断线、正在等确认、麦克风关着 | 不自动接话 |

细节：**「说完了」不再靠字数估**。球窗每排一片音频就把「排空时刻」往后顺延，真播空了才通过
`speech:drained` 回报主进程；主进程收到才开麦。以前是按字数估，估早了就自动开麦，而球窗一看到
状态变成 `listening` 就把还在播的音频掐掉——表现就是「话说一半没了」。现在 `listening` 状态
不再掐音频，只有唤醒 / 插话 / 面板「停止」才发 `speech:stop` 真静音。
再喊一次唤醒词时，按设置重新决定要不要连续。

## 6. 主题与换肤

两件事分开：

- **主题**（纸 / 墨 / 跟随系统）走 Electron 的 `nativeTheme.themeSource`，`panel.css` 里用的是
  `@media (prefers-color-scheme: dark)`，所以改一处、面板所有窗口一起变。
- **换肤**（角色贴图）是「文件 + 索引」：导入的图存在 `userData/skins/`，键名 `user-xxxx`。

修掉的老坑：`store.ts` 的 `normalizeSkin()` 原来只认 `whale | niang02`，自定义键一保存就被
改成 `whale` —— 表现就是「能导入、但切换没反应」。现在只做形状校验，真正存不存在交给
`ipc.ts` 的 `resolveSkinKey()`（不存在的键退回鲸鱼娘）；导入成功后主进程直接把它设成当前皮肤并广播。

### 贴图列表的排版（两个坑）

1. **不能用 `<button>` 当格子**：Chrome 的按钮有自己的布局算法，`display: flex` 基本不生效，
   子元素仍按行内流排——名字一长就横向顶出去，还会压住缩略图。改成 `div[role=button][tabindex=0]`
   （回车/空格可激活），flex 列布局才真正生效。
2. **网格比一行分段按钮稳**：`grid-template-columns: repeat(auto-fit, minmax(76px, 1fr))`，
   名字 `overflow: hidden + text-overflow: ellipsis`，格子 `overflow: hidden`；容器
   `max-height: 230px`（正好三行）超出滚动。第一个格子固定是「导入图片」，贴图再多也够得着。

### 右键编辑

自己导入的贴图（键名 `user-*`）右键弹出小菜单：**改名 / 删除**。
菜单是 `position: fixed` 并按视口夹紧的，不会被 `.settings` 的滚动裁掉；点外面或 Esc 关掉。
改名走 `skin:rename`（只动 `index.json` 里的显示名，图与键都不动），删除走 `skin:remove`
（删的是当前那张就自动退回鲸鱼娘）。设置页里改名或开着菜单时按 Esc 只关那一层，不会把面板收起来。
