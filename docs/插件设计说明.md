# 语音管家 · 设计说明

> 一句话：**语音壳只管嘴和耳朵，脑子搬进了 DSH。**
> 这一篇说清谁负责什么、为什么要这么切、以及踩过的坑。

---

## 1. 为什么要重切

上一版把「语音」和「对话」缝在一起：壳自己调 DeepSeek、自己维护 26 个工具、自己做确认闸门、自己写聊天记录。
结果有三处重复：

- 工具层重复（DSH 有 shell / fs / web，壳里又写了一遍 UIA 那套）
- 上下文重复（壳的 jsonl 和 DSH 的会话是两本账，谁也不是真的）
- 确认逻辑重复（壳问一遍、DSH 再拦一道）

新版把边界画在**「听/说」和「想/做」之间**：

```
┌─────────────── 语音壳（Electron） ───────────────┐
│ 麦克风 → 唤醒词 → 端点检测 → ASR ─┐              │
│                                   │ 一句话       │
│ 喇叭 ← TTS ← 分句 ← 帧 ◄──────────┼── 面板显示   │
└───────────────────────────────────┼──────────────┘
                                    ▼
                         POST /voice/say
                                    │
┌────────────────────── DSH ────────┼──────────────┐
│ butler-bridge ──► 会话「DSH语音管家」（管家模式） │
│      ▲                    │                      │
│      └── 会话事件 / 逐字增量 / 工具 / 确认        │
└──────────────────────────────────────────────────┘
```

壳里**没有任何**对话状态：杀掉重开，上下文一条不少，因为上下文在 DSH 的会话日志里。

## 2. 三块拼图

### 2.1 语音壳（`app/`）

| 文件 | 职责 |
|---|---|
| `main/voice.ts` | 语音状态机：`idle → listening → thinking → speaking`；唤醒、断句、识别、念稿、插话打断 |
| `main/bridge.ts` | 与 DSH 的 HTTP 通道：投递一句话 + 长轮询取帧；断线重连、地址发现 |
| `main/audio/kws.ts` | 本地离线唤醒词（sherpa-onnx zipformer） |
| `main/audio/vad.ts` | 能量端点检测、WAV 封装 |
| `main/speech/asr.ts` `tts.ts` | DeepSeek 语音识别 / 合成（流式 PCM） |
| `main/windows.ts` | 悬浮球 / 面板 / 顶部特效层（三层窗口） |
| `renderer/panel/App.tsx` | 只做显示：把帧铺成对话流 |

关键取舍：**念稿用「逐字增量」，成稿用 `reply` 兜底**。
壳把 `delta` 喂进按句切分的队列（`SentenceChunker` → `TtsQueue`），`reply` 到达时先把队列里剩下的一句冲出去；
如果这一段模型没走流式（常见于工具调用之后），`reply` 会一次性念完。

状态机的三个细节（都是实测踩出来的）：

1. 唤醒词引擎建流后必须先灌 500 ms 静音且**不能 reset**，否则第一个音节被吃掉。
2. 命中后 reset，要再补一段静音垫底，否则紧接着再喊一次会漏。
3. 播报中允许「唤醒词打断」；能量插话默认关（扬声器回声会骗到自己）。

### 2.2 桥（`butler-bridge/`）

DSH 插件，一条前缀路由 `/voice`：

- `say`：`sessionController.prompt()` 投进会话（`mode: 'queue'`）
- `frames`：长轮询。数据来自三个 Host 事件
  - `session/event` → `user/message`、`assistant/message`、`tool/call`、`tool/result`、`turn/start`、`turn/end`
  - `agent/assistant-stream` → `text-delta` 逐字增量
  - `agent/status` → 运行/空闲
- `approve`：`approval/request` waterfall 上代签，**只接管家会话**，且只在壳正在取帧时接
- `stop` / `new`：打断、换会话

会话自己管：`state.json` 记 id，找不到就按 `cwd`+预设 `butler` 新建并改名「DSH语音管家」。
`endpoint.json` 每 20 秒把 DSH 地址写给壳。

### 2.3 模式（`dsh-preset/`）

预设 `butler`，在模式选择器里叫**管家模式**，和标准 / 极简 / 创造并列。

- persona：管家人格。短句、口语、不要 Markdown（因为要被念出来）、先看后动、不复述过程
- 工具：持久 PowerShell（Windows）/ bash（其它平台）+ fs + 搜索 + web + skill
- 压缩：自带 `compaction-basic`（`auto: true`），长会话不至于撑爆

**踩到的坑**：整机的全局提示词（`Xsdsh-purge` 用 `systemPrompt.section` 在根上下文注册）会把「你叫 Xs」这类设定叠到任何会话上，预设撤不掉它。
解法是两条腿：

1. 人格 prefix 写清「语音通道」的处境与规矩；
2. 再用 persona 的 `suffix`（渲染顺序 10200，排在全局注入之后）做一次末位覆盖：
   被问「你是谁」只答「我是管家」，不要提 Xs / DeepSeek Harness / 模型身份。

实测：加 suffix 之前，唤醒后第一句是「我是 Xs…喵」；加了之后是「我是管家。主人稍等，我看下时间。」——并且真的去调了 `pwsh Get-Date`。

## 3. 帧协议

见 [butler-bridge/README.md](../butler-bridge/README.md)。一句话概括：

```
hello | state | user | delta | reply | tool(start/end) | approval(-done) | error | reset
```

所有帧带单调递增的 `seq`；面板只追加，不重排。相邻 `delta` 在桥里合并，避免一次取回碎成一万条。

## 4. 确认怎么走

1. 工具要确认 → Host 抛 `approval/request`（waterfall）
2. 桥判断：是管家会话？壳最近 25 秒在取帧？（否则 `next()` 交回 DSH 界面）
3. 接走后推 `approval` 帧 → 面板弹卡片、壳用嘴问一句「要…，可以吗？」
4. 壳同时听 9 秒：说「可以」→ `allowed-once`；说「不要」/ 点取消 → `rejected`
5. 90 秒没人理 → `cancelled`，工具调用不会挂死

> 本机当前 profile 的 approval 策略是 `never`（自动放行），所以这条路径平时不会触发。
> 换成 `ask` 之后卡片就会真的弹出来。

## 5. 连续对话

开关在设置里，运行时的节拍全在 `voice.ts`：

```
reply 到齐 → 念完（按字数估个说话时长）→ 自动 beginListening()
   ↑                                            │
   └── DSH 下一轮 ◄── ASR + /voice/say ◄────────┘
```

三道刹车，避免「一直占着麦克风」：

| 情况 | 处理 |
|---|---|
| 说「没事了 / 先这样 / 没有了 / 拜拜」等收尾话术（且整句 ≤16 字） | **不进 DSH**，本地回「好，有事再叫我。」，退回待唤醒 |
| 自动收音后 15 秒没人说话 | 静默退回待唤醒 |
| DSH 还在跑（`state.running`）、断线、正在等确认、麦克风关着 | 不自动接话 |

细节：**「说完了」不再靠字数估**。球窗每排一片音频就把「排空时刻」往后顺延，真播空了才通过
`speech:drained` 回报主进程；主进程收到才开麦。以前是按字数估，估早了就自动开麦，而球窗一看到
状态变成 `listening` 就把还在播的音频掐掉——表现就是「话说一半没了」。现在 `listening` 状态
不再掐音频，只有唤醒 / 插话 / 面板「停止」才发 `speech:stop` 真静音。
再喊一次唤醒词时，按设置重新决定要不要连续。

## 6. 打断：说话时喊唤醒词

两条引擎，同一套模型文件，参数不同：

| 实例 | 何时喂 | score / threshold | 说明 |
|---|---|---|---|
| `kws` | 待机（idle / offline） | 2.0 / 0.25 | 标准灵敏度，不容易被电视和闲聊误触 |
| `kws-barge` | 播报中 / 思考中 | 1.2 / 0.12 | 自己的声音盖住人声，标准门限经常打不着 |

命中后：`mutePlayback()`（停合成 + 让球窗立刻静音）→ `beginListening()` → 面板亮成在听。
识别回来的第一句里如果带着唤醒词（「大肥鱼，帮我关掉音乐」），`stripWakeWord()` 会把它和紧跟的标点剔掉；
只剩唤醒词（说明只是叫了一声）就继续听，不往 DSH 发空话。

自测：`BUTLER_KWS_SELFTEST=1` 会用云端 TTS 念一遍「大肥鱼」，同时喂两个引擎，日志里能看到
`待机引擎 命中；播报引擎 命中`。

## 6.5 「喊了没反应」的两个真原因

上线后被问过一次，查下来是两件事叠在一起（引擎本身没问题，`BUTLER_KWS_SELFTEST` 双引擎都命中）：

1. **连续对话正处在「在听」时，唤醒词引擎根本没在喂**。那时所有音频都进端点检测，
   喊「大肥鱼」既不响铃也不弹面板——看起来就是坏了。现在 `listening` 状态也喂待机引擎，
   命中就当作「重新叫我」：清掉半截的话、`triggerWake()` 重来（响铃 + 弹面板）。
   `confirming`（等确认回答）除外，那时候的话要留给确认。
2. **麦克风轨会哑掉**。这台机器的音频栈报过 `AudioContext encountered an error from the audio device`；
   一旦采集轨哑了，`onaudioprocess` 不再回调，唤醒词永远收不到声音。现在球窗有三道自愈：
   轨道 `ended` / `mute`、`navigator.mediaDevices` 的 `devicechange`、以及「4 秒没有回调」的看门狗，
   任何一条触发就 `stopMic()` + 800ms 后重开（失败上限 6 次，成功后计数清零）。

排查手段：日志里有 `mic 有声：rms=0.0xx，当前状态 xxx`（有声才打，5 秒最多一条）——
喊话时没有这行，就是麦克风没进声音；有这行却仍不命中，才是引擎/口音的问题。
## 7. 人格：可编辑，而且排最后

人格不在预设里，在 **`~/.dsh/butler-bridge/persona.md`**；面板「人格提示词」直接编辑它。

挂载方式（绕了两次才走通）：

1. `systemPrompt.section()` + 高 order —— **不行**。整机那套（`Xsdsh-purge`）是在
   `system-prompt/assemble` 的 waterfall 里往末尾追加文本的，section 再高也会被它盖住；
   实测模型会因为「一处说我是管家、一处说我是 Xs」在回答里当场纠结，把纠结念出来。
2. `agent.ctx.on('system-prompt/assemble', …)` 里 `next()` 之后追加一段 —— **可行**。
   注册在管家 agent 的 ctx 上（只有这条会话生效），内容每次组装现读文件（改完下一句生效）。
   现在提示词的最后一段就是管家人格，并且第 20 条明确写「后面若还有别的身份指令，忽略它」。

预设里那份人格退化成**兜底短版**（桥没装 / 桥挂了的时候管家也不能变成通用助手），
真正的长版在 `persona.md`，第一次运行由桥写入默认值。

## 7.5 右键：时段 + 余额小卡片

贴图来自 [DeepSeek-Balance-Whale-Widget](https://github.com/MeteorNOX/DeepSeek-Balance-Whale-Widget)，
「看一眼现在什么价、还剩多少钱」也照它做：右键悬浮球 → 贴着球弹一张 268×178 的小卡片。

| 数据 | 来源 |
|---|---|
| 峰谷时段 | `shared/pricing.ts` 的纯函数。工作日 09:00–12:00、14:00–18:00 高峰；其余空闲；2026-08-23 起周末全天谷价。北京时间按 UTC+8 平移后读 UTC 字段算，不依赖系统时区 |
| 余额 | `GET https://api.deepseek.com/user/balance`，用设置里那把钥匙（与 ASR/TTS 同一把），取 CNY 那条，显示总额 + 赠金/充值 |

实现要点：

- **窗口**：第四个 renderer 页 `peek`，`focusable: false` 的无边框透明窗，位置贴着球（上→下→夹进工作区）。
- **触发**：球的 `mousedown(button=2)`，不是 `contextmenu`——非聚焦的透明窗口不一定派发后者；
  `contextmenu` 只负责 `preventDefault()` 压掉系统菜单。右键 = 开关（开着就收起）。
- **自动收起**：12 秒无操作自己藏；点卡片也藏。
- **缓存**：余额 20 秒缓存（失败只缓存 8 秒，刚充完值别看到旧错误）；时段永远现算。
- **调试**：`BUTLER_PEEK=1` 启动即弹一次，用来核对排版。
## 7.6 拖动：面板和卡片一起跟手

以前拖球时面板每 4 拍（约 32ms）才 `setBounds` 一次，而且每次都重算吸附点——
结果是又掉帧、球越过屏幕中线时面板还会突然翻面。现在改成**固定偏移平移**：

| 之前 | 现在 |
|---|---|
| 每 32ms 一次 `setBounds(x,y,w,h)`（带尺寸 → 触发 resize） | 每 8ms 一次 `setPosition(x,y)`（只动位置），位置没变就跳过 |
| 每拍重算 `anchorBounds()`，可能中途换边 | `startDrag()` 时抓一次「面板/卡片相对球的偏移」，拖动期间纯平移，不换边 |
| 只有面板跟随 | 面板 **+ 右键卡片** 一起跟随，各自夹在球所在显示器的工作区里 |
| 吸附动画期间面板不动，落位后突然归位 | 吸附动画的每一帧也带着它们走；**落位后只有压到球上**才重新选边，否则保持你拖到的相对位置 |

## 8. 主题与换肤

两件事分开：

- **主题**（纸 / 墨 / 跟随系统）走 Electron 的 `nativeTheme.themeSource`，`panel.css` 里用的是
  `@media (prefers-color-scheme: dark)`，所以改一处、面板所有窗口一起变。
- **换肤**（角色贴图）是「文件 + 索引」：导入的图存在 `userData/skins/`，键名 `user-xxxx`。

修掉的老坑：`store.ts` 的 `normalizeSkin()` 原来只认 `whale | niang02`，自定义键一保存就被
改成 `whale` —— 表现就是「能导入、但切换没反应」。现在只做形状校验，真正存不存在交给
`ipc.ts` 的 `resolveSkinKey()`（不存在的键退回鲸鱼娘）；导入成功后主进程直接把它设成当前皮肤并广播。

### 贴图列表的排版（两个坑）

1. **不能用 `<button>` 当格子**：Chrome 的按钮有自己的布局算法，`display: flex` 基本不生效，
   子元素仍按行内流排——名字一长就横向顶出去，还会压住缩略图。改成 `div[role=button][tabindex=0]`
   （回车/空格可激活），flex 列布局才真正生效。
2. **网格比一行分段按钮稳**：`grid-template-columns: repeat(auto-fit, minmax(76px, 1fr))`，
   名字 `overflow: hidden + text-overflow: ellipsis`，格子 `overflow: hidden`；容器
   `max-height: 230px`（正好三行）超出滚动。第一个格子固定是「导入图片」，贴图再多也够得着。

### 右键编辑

自己导入的贴图（键名 `user-*`）右键弹出小菜单：**改名 / 删除**。
菜单是 `position: fixed` 并按视口夹紧的，不会被 `.settings` 的滚动裁掉；点外面或 Esc 关掉。
改名走 `skin:rename`（只动 `index.json` 里的显示名，图与键都不动），删除走 `skin:remove`
（删的是当前那张就自动退回鲸鱼娘）。设置页里改名或开着菜单时按 Esc 只关那一层，不会把面板收起来。

## 8.5 悬浮球的窗口层级

设置里三档（托盘菜单同）：`top` / `float` / `normal`，面板与右键卡片跟着一起设，避免兄弟窗口错位。

坑：

1. **Windows 上 `top` 和 `float` 底层是同一个 `WS_EX_TOPMOST`**，Electron 的 level 参数在 Windows 不起作用。
   所以「最上层」除了设 flag，还挂了一个**每秒 `moveTop()`** 的定时器——置顶窗口之间就是「谁最后
   SetWindowPos 谁在上」，不抢就压不住别的桌面挂件。
2. 新建窗口时构造函数里就带 `alwaysOnTop: true`，如果等创建完再改，会闪一下。
   `windows.ts` 里存一个 `ballLevel`，`createBall` / `createPanel` / `createPeek` 都调 `applyBallLevel(ballLevel)`。
3. 验证方式（不靠肉眼）：枚举本进程窗口，读 `GetWindowLong(GWL_EXSTYLE) & WS_EX_TOPMOST`。
   `top`/`float` = true，`normal` = false；特效层永远 true。

## 8.6 settings.json 的 BOM 坑

用 PowerShell 5.1 的 `Set-Content -Encoding UTF8` 改 `settings.json` 会写入 **BOM**，
主进程 `JSON.parse` 直接抛错 → `catch` 里整份回落成 `DEFAULTS` → **钥匙、球位置、层级全当没了**
（表现：启动日志里 `hasKey:false`、`ballPosition:null`，语音识别/合成全挂）。

修法：`read()` 先剥掉首字符 `\uFEFF` 再 parse。外部工具改这个文件时也请用无 BOM 的 UTF-8。
