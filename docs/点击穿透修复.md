# 「点一下之后就一直穿透」的修复记录

## 症状

点鲸鱼 → 面板开/关一次 → 之后再点就没反应，鼠标事件穿到桌面去了。要先把鼠标移开再移回来才恢复。

## 根因（两层）

1. **状态镜子对不上**：`setIgnoreMouseEvents` 有两处调用点，其中 `panel.on('hide')` 直接调原生 API 把窗口设成穿透，却绕过了轮询里的 `interactive` 变量。轮询下一拍算出「光标在球上、应该可交互」，发现 `next === interactive`（都是 true），于是**提前 return，不再调原生 API** —— 窗口就永远保持穿透。
2. **系统需要鼠标移动才重算命中**：Windows 在 `WS_EX_TRANSPARENT` 被加上/去掉之后，要等下一次鼠标移动才重新做窗口命中测试。所以「刚点完、手没动」的那一下最容易丢。

第 1 条是我上一版声称修好却没修好的原因：我修了 enter/leave，没修这个直接调用。

## 现在怎么修

**把穿透整个删了。** 球窗永远是普通窗口：

```ts
ball.setIgnoreMouseEvents(false)   // 唯一的调用，且只传 false
```

- 删掉了 60ms 的轮询、`setIgnore`/`refreshBallInteractive`/`hitTest`、渲染层的 `setInteractive` 通道。
- 窗口从 128×128 缩到 **112×112**（鲸鱼 104），四角透明区域很小，当作「不挡桌面」与「一定能点」之间的取舍。
- 悬停动画改回纯 CSS `:hover`（窗口一直可交互，这个事件是可靠的）。

## 证据

**结构上不可能再穿透**（源码与构建产物都只有一处 `false`）：

```
$ Select-String -Path src\**\*.ts,src\**\*.tsx -Pattern "setIgnoreMouseEvents"
windows.ts:74  ball.setIgnoreMouseEvents(false)
$ Select-String -Path out\main\index.js -Pattern "setIgnoreMouseEvents"
index.js:510   ball.setIgnoreMouseEvents(false)
```

**行为验证**（旧版修好状态镜子那一轮，鼠标全程不动连点 5 次）：

```
click 1: panel=False  (原来开着 → 收起)
click 2: panel=True   (重新打开)
click 3: panel=False
click 4: panel=True
click 5: panel=False
```

同时日志里每次点击都成对出现 `togglePanel visible=...` + `hidePanel`，说明 5 次点击全部落到了球窗上。

## 复现脚本

`app/scripts/click-test.ps1`：枚举 112×112 的球窗、把光标放到球心、连点 5 次、每次比对面板可见性是否翻转。

> 注意：鼠标被真人占用时脚本会打印 `SKIP cursor busy`（`SetCursorPos` 会被物理移动顶掉）。跑之前手离开鼠标 10 秒。
