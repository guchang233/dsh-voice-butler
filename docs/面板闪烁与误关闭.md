# 面板闪烁 · 对话完自动收起

## 症状

1. 点鲸鱼打开面板时闪一下。
2. 每次对话结束（点了「发送」或者说完话）面板就自己收起来。

## 根因

### ① 球压住了面板的「发送」键

球窗（112×112）在右下角，面板从球的正上方展开：

```
panel  1492,216 .. 1912,836
ball   1778,781 .. 1890,893
       ^^^^^^^^^^^^^ 底部 55px 重叠，正好是 composer + tab 栏
```

球窗是 `screen-saver` 层级且**永远可点**（上一轮为了修穿透问题改的），所以点面板右下角的「发送」，实际点到的是球 → 触发 `togglePanel()` → 面板收起。看起来就是「说完话窗口自己关了」。

### ② 透明窗口先摆位置再显示

`showPanel()` 原来的顺序是 `setBounds()` → `show()` → `moveTop()`。透明窗口在 `show()` 的那一帧可能按旧位置/未合成的状态先画一次，肉眼就是闪一下。

### ③ 拖拽阈值太紧，点一下被吃成拖拽

`Orb.tsx` 里位移超过 **3px** 就判定为拖拽。手抖一两像素、系统 DPI 抖动，都会让「点一下」变成「拖了一下」，于是不触发 toggle —— 表现为偶尔「点一下没反应」。

## 修法

| 问题 | 改动 |
|---|---|
| ① | `anchorBounds()` 改成三级避让：先上下贴球，不行就挪到球的左右，再不行才兜底；同时新增 `syncPanelToBall()`，球吸附到位后让面板跟着让位 |
| ② | `showPanel()` 先 `setOpacity(0)` 再 `show()`，60ms 后 `setOpacity(1)`；去掉 `moveTop()` |
| ③ | 拖拽阈值 3px → **8px** |

避让算法（`windows.ts`）：

```ts
// ① 优先上下贴球
for (const top of [preferTop, !preferTop]) { ... if (fits(x, yy)) return {x, y: yy} }
// ② 上下都让不开（球停在屏幕中间）：挪到球的左右
for (const top of [preferTop, !preferTop]) for (const raw of sideX) { ... }
// ③ 屏幕太小实在塞不下，退回最合理的一侧
```

## 验证

`app/scripts/panel-test.ps1`（枚举窗口 → 算矩形 → 注入真实点击）：

```
ball=1794,783 112x112  panelVisible=False
after ball click: panelVisible=True
panel=1492,151..1912,771
ball =1794,783..1906,895
overlap=112x0  PASS no overlap
click panel 1852,716 -> stillOpen=True  PASS
click panel 1822,716 -> stillOpen=True  PASS
click panel 1692,716 -> stillOpen=True  PASS
panel-clicks kept open: 3/3
```

`app/scripts/click-test.ps1`（球上连点 5 次，鼠标全程不动）连跑两轮：

```
round 1: click 1..5 全部 PASS  result: 5/5
round 2: click 1..5 全部 PASS  result: 5/5
```

日志里每次点击都成对出现 `togglePanel visible=…` + `hidePanel` / `showPanel`，5 次点击 5 次都落到球窗上。

## 还留着的行为

- 点面板右上角 ✕、按 `Esc`、托盘「收起面板」——这三种仍然会收面板，是设计如此。
- 面板开着的时候拖球，面板会在球吸附到位后跟着让位（拖动过程中可能短暂重叠，松手即修正）。
